The Compose bundle runs everything on one host. Read [Requirements](/docs/incuscloud/install/requirements)
first.

<Steps>
<Step>

### Get the bundle

From a release:

```bash
V=0.1.0   # the release: github.com/m41denx/incendio/releases (tags incuscloud-v*)
curl -fsSLO https://github.com/m41denx/incendio/releases/download/incuscloud-v$V/incuscloud-compose-$V.tar.gz
tar xzf incuscloud-compose-$V.tar.gz && cd incuscloud-compose-$V
```

Or from the repository:

```bash
git clone https://github.com/m41denx/incendio && cd incendio/incuscloud/deploy/compose
```

### Run setup

Run it as the user who will own the install: the containers run as that user, so they can read the
keys in `./certs`.

```bash
./setup.sh --host cloud.example.com \
           --cluster-domain clusters.example.com \
           --admin admin@example.com \
           --openfga-host 10.0.0.5
```

<TypeTable
  type={{
    "--host": { type: "name", description: "The public host.", required: true },
    "--cluster-domain": { type: "name", description: "The domain for the cluster APIs.", required: true },
    "--admin": { type: "email", description: "The first platform administrator.", required: true },
    "--openfga-host": { type: "address", description: "The address the Incus clusters use to reach this host's port 8080.", default: "--host" },
  }}
/>

It writes three things, readable by you only:

| File | Holds |
| --- | --- |
| `.env` | Compose's settings: database passwords, Hydra's secret, OpenFGA's key, the image, and the addresses ports are published on (`IC_BIND`, `OPENFGA_BIND`) |
| `incuscloud.env` | IncusCloud's settings, including `IC_SECRET_KEY` and the first admin's password, `IC_BOOTSTRAP_ADMIN_PASSWORD`. See the [settings reference](/docs/incuscloud/operations/configuration) |
| `certs/` | `ca.crt` and `ca.key` (the internal CA), `hydra.crt` and `hydra.key`, and `public/tls.crt` and `tls.key` for IncusCloud |

Running it again keeps what exists, so it never rotates a secret by surprise.

<Callout type="warn" title="Back up incuscloud.env now">
  `IC_SECRET_KEY` seals the client keys IncusCloud uses for each cluster. Lose it and you lose every
  enrolled cluster.
</Callout>

</Step>
<Step>

### Use your own certificate

Skip this step with the internal CA. Otherwise replace the generated certificate, before the first
start or any time after:

```bash
cp /etc/letsencrypt/live/cloud.example.com/fullchain.pem certs/public/tls.crt
cp /etc/letsencrypt/live/cloud.example.com/privkey.pem   certs/public/tls.key
chmod 600 certs/public/tls.key
docker compose restart incuscloud
```

For renewals, a certbot deploy hook can do the same.

</Step>
<Step>

### Start

```bash
docker compose up -d
docker compose ps                  # the two *-migrate services exit 0, the rest run
docker compose logs -f incuscloud  # wait for "listening"
```

Check that sign-in is served on the public host:

```bash
curl --cacert certs/ca.crt https://cloud.example.com/.well-known/openid-configuration
# {"issuer":"https://cloud.example.com/", ...}
```

Drop `--cacert` with a public certificate. The issuer must be exactly `https://<public host>/`.

</Step>

## Ports

| Port | Service | Published on |
| --- | --- | --- |
| 443 | IncusCloud | `IC_BIND` (all addresses by default) |
| 8080 | OpenFGA | `OPENFGA_BIND` (all addresses by default) |

Hydra and Postgres are never published. On a host with a public and a private interface, set
`OPENFGA_BIND` to the private address the clusters use, then run `docker compose up -d` again.

To put IncusCloud behind an existing load balancer on the same host, publish 443 elsewhere (edit
`ports` under `incuscloud`) and forward TCP with TLS passthrough: HAProxy `mode tcp`, or nginx
`stream`.

## Building the image from source

From `incuscloud/deploy/compose` in a clone:

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

Or only the image, from the repository root:

```bash
docker build -f incuscloud/Dockerfile --build-arg GIT_HASH=$(git rev-parse --short HEAD) -t incuscloud:local .
```
